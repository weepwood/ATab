# 本地网页资源索引

ATab 的网页资源索引用于保存用户主动选择的网页正文，并为全文搜索、后续 AI 摘要和向量语义检索提供统一数据入口。

第一阶段严格采用本地优先策略：正文只写入扩展 IndexedDB，不自动进入云同步、AI Provider 或第三方接口。

## 用户流程

```text
打开“网页资料”工作台
  ↓
从当前已打开标签页中选择一个 HTTP/HTTPS 页面
  ↓
点击“保存网页正文”
  ↓
浏览器按当前网站请求主机权限
  ↓
重新检查标签页 URL 未发生变化
  ↓
通过 chrome.scripting.executeScript 提取正文
  ↓
规范化 URL、清理文本、计算 SHA-256
  ↓
在同一 Dexie 事务中写入 resources + resourceContents
```

没有用户点击时，ATab 不会读取页面正文。

## 权限模型

Manifest 只声明：

- `activeTab`：保留浏览器显式用户操作下的临时访问能力；
- `scripting`：允许执行确定性的正文提取函数；
- HTTP/HTTPS 可选主机权限：只有用户保存具体网站时才请求。

扩展安装时不申请 `<all_urls>`，也没有持久注入所有网页的 content script。

用户可以在浏览器扩展设置中撤销已授权网站。权限撤销不会删除已经保存在本地的资源快照。

## 数据模型

### `resources`

保存页面级元数据：

- 原始 URL 与规范化 URL；
- 标题、域名、favicon；
- 描述和语言；
- 正文哈希与字符数；
- 首次发现、最近保存和正文采集时间；
- AI 摘要与向量化状态占位字段。

### `resourceContents`

每个资源只保存一份当前正文快照：

- `resourceId`；
- 完整正文；
- 列表摘要；
- SHA-256 内容哈希；
- 字符数和粗略词元数；
- 采集时间。

同一规范化 URL 再次保存时更新原资源，不创建重复项，并保留最初的 `firstSeenAt`。

## 正文提取

采集函数优先选择：

```text
article → main → [role="main"] → body
```

提取时忽略：

- script、style、noscript；
- svg、canvas；
- nav、header、footer、aside；
- form、button、input、textarea、select；
- hidden 和 `aria-hidden="true"` 节点。

当前单页最大保存 200,000 字符。正文短于 80 字符时拒绝保存，避免把空白页、登录壳页面或无法读取的客户端应用误存为正文。

## 敏感页面提示

ATab 会根据 URL 和标题对下列页面给出额外确认：

- 登录与认证；
- 支付、结算和银行页面；
- 邮箱与收件箱；
- 患者、医疗和病案页面。

这只是客户端提示，不代表页面内容已经上传。用户取消后不会读取或保存正文。

## 本地全文搜索

统一搜索新增“网页资料”来源：

- 标题和 URL 使用较高权重；
- 描述、语言和域名作为关键词；
- 正文命中权重低于标题和元数据；
- 单条正文只取前 50,000 字符参与即时搜索，避免大型页面阻塞输入；
- 搜索词、正文和结果都不发送给 AI 或同步服务。

资源库自身搜索可以检索完整本地正文。

## 安全边界

- 网页正文始终是不可信数据，不能成为系统指令；
- 保存正文不会自动创建云同步变更；
- `summaryStatus` 和 `embeddingStatus` 默认是 `not-requested`；
- 删除快照只删除 ATab IndexedDB 中的资源与正文；
- 不修改浏览器历史、原生书签、云收藏或当前网页；
- 服务端模型密钥和用户同步凭据不会写入资源内容。

## 后续演进

下一阶段可以在独立授权下增加：

1. 用户主动选择正文片段发送到 AI Provider 生成摘要；
2. 对正文分块并生成嵌入向量；
3. 本地关键词结果与远端向量结果融合；
4. 单独的正文同步开关和端到端加密选项；
5. 内容版本历史和变更对比。

这些能力不得复用笼统的“启用 AI”开关，必须分别说明上传数据范围和保存位置。

## 验证

```bash
pnpm typecheck
pnpm test
pnpm build
```

CI 不能替代真实浏览器测试。仍需人工验证：权限申请与撤销、受 CSP 保护页面、单页应用、跨域 iframe、超长正文和敏感页面确认。
