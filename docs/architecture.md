# ATab 总体架构

## 1. 产品边界

ATab 采用“浏览器扩展 + 云同步服务 + AI 编排服务”的形态，不维护 Chromium 内核。

扩展负责真实浏览器操作；服务器负责账号、同步、索引和模型调用。服务器不能直接调用用户浏览器里的 `chrome.tabs`、`chrome.bookmarks` 或 `chrome.tabGroups`。

## 2. 逻辑架构

```text
用户
  ├─ 新标签页
  ├─ 标签页工作台
  └─ 设置页
        ↓
浏览器适配层
  ├─ Tabs
  ├─ Tab Groups
  ├─ Bookmarks
  ├─ Sessions
  └─ Storage
        ↓
本地数据层（IndexedDB）
        ↕ 增量同步
应用 API / BFF
  ├─ 认证与设备
  ├─ 资源与收藏
  ├─ 同步服务
  ├─ AI 编排器
  ├─ 策略与审计
  └─ 异步任务
        ↓
PostgreSQL + pgvector + 对象存储
```

## 3. 扩展入口

- 新标签页：搜索、快捷网站、最近标签和工作空间入口。
- 工作台：多窗口、标签组、会话、书签和 AI 指令。
- 设置页：数据采集、模型和同步权限。
- Service Worker：浏览器事件、命令入口和同步调度。

Chrome 109 不具备稳定的 Side Panel 能力，所以侧边栏只能作为新版本增强，不能成为唯一入口。

## 4. AI 分层

1. 意图识别：搜索、总结、分类、整理或执行操作。
2. 混合检索：SQL 条件、全文检索、向量检索和时间过滤。
3. 计划器：输出严格结构化的操作计划。
4. 策略层：风险分级、权限校验、目标对象校验。
5. 扩展执行器：调用白名单浏览器 API。
6. 审计与撤销：记录计划、确认、执行结果和反向操作。

## 5. 部署演进

### 第一阶段

只有浏览器扩展和本地数据库，AI 使用本地确定性规则验证操作链路。

### 第二阶段

加入 API、账号、云同步和只读 AI 能力。

### 第三阶段

开放受控写操作、语义检索、自动化和跨设备会话恢复。
