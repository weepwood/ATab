# 浏览历史工作台

ATab 的浏览历史模块采用按需授权和只读优先设计。

## 权限模型

Manifest 只声明：

```json
{
  "optional_permissions": ["history"]
}
```

扩展安装时不会自动获得浏览历史权限。只有用户进入“历史”工作台并点击授权按钮时，才调用：

```text
chrome.permissions.request({ permissions: ['history'] })
```

每次刷新前都会重新调用 `chrome.permissions.contains`，因此用户在浏览器扩展设置中撤销权限后，界面会自动退回未授权状态。

## 本地数据边界

历史查询结果：

- 直接来自 `chrome.history.search`；
- 只在当前页面内存中展示；
- 不写入 IndexedDB；
- 不进入同步 Outbox；
- 不自动发送给 AI 或同步服务；
- 只展示 HTTP 和 HTTPS 页面。

当前隐私设置中的“同步浏览历史”仍保持关闭且未实现上传逻辑。

## 查询能力

支持：

- 最近 1 天；
- 最近 7 天；
- 最近 30 天；
- 最近 90 天；
- 标题与 URL 关键词查询；
- 按本地日期分组；
- 显示访问次数、手动输入次数和最后访问时间。

单次查询结果上限默认为 2000 条，代码层限制最高 10000 条，避免一次读取过多历史导致界面阻塞。

## 删除操作

删除前会显示明确确认框。确认后只调用：

```text
chrome.history.deleteUrl({ url })
```

它只删除所选 URL 的历史记录，不会：

- 清空全部历史；
- 删除书签；
- 删除云收藏；
- 关闭当前标签页。

## 保存到云收藏

用户可以主动把某条历史保存到云收藏：

1. 使用规范化 URL 查询本地 `cloudBookmarks`；
2. 已存在时不重复创建；
3. 不存在时创建云收藏；
4. 文件夹默认为“浏览历史”；
5. 标签默认为 `history`；
6. 云收藏与 Outbox 在同一 Dexie 事务中写入。

保存到云收藏不会修改或删除原始历史记录。

## 当前限制

- 尚未提供按域名统计图表；
- 尚未提供批量删除；
- 尚未提供历史跨设备同步；
- 尚未提供 AI 浏览行为分析；
- 查询使用 Chrome History API 自带的文本匹配，尚未接入语义检索。
