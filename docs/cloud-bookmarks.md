# 云收藏与原生书签导入

ATab 将浏览器原生书签和云收藏设计为两个独立数据层。

## 数据边界

### 原生书签

- 数据唯一来源是 `chrome.bookmarks`；
- Chrome/Edge 自己负责原生书签同步；
- ATab 可以浏览、编辑、移动和删除原生书签；
- 不直接把完整原生书签树做双向云同步。

### 云收藏

- 数据保存在 ATab IndexedDB 的 `cloudBookmarks` 表；
- 每条记录都可以包含文件夹路径、标签、备注和归档状态；
- 新增、修改和删除会写入 `syncOutbox`；
- 登录并启用同步后，使用 `cloud-bookmark` 实体跨设备同步；
- 删除云收藏不会删除浏览器原生书签。

## 云收藏记录

```text
id
标题
原始 URL
规范化 URL
文件夹路径
标签
备注
归档状态
来源
原生书签来源 ID（可选）
创建时间
更新时间
```

文件夹目前采用路径字段，例如：

```text
工作 / 前端 / Vue
```

这样可以在不引入独立文件夹实体和复杂移动冲突的情况下，先提供稳定的分组和跨设备同步。

## URL 去重

ATab 会：

- 自动补全 `https://`；
- 仅接受 HTTP 和 HTTPS；
- 移除常见追踪参数；
- 移除页面锚点；
- 统一主机名大小写；
- 移除非根路径末尾的多余斜杠。

导入预览和实际写入前都会再次按规范化 URL 检查重复项，避免预览后本地数据变化造成重复写入。

## 从原生书签导入

导入流程：

```text
读取 chrome.bookmarks 树
  ↓
展开文件夹路径
  ↓
过滤不可同步协议
  ↓
规范化 URL
  ↓
标记已有或树内重复项
  ↓
用户选择导入项
  ↓
复制到 cloudBookmarks + syncOutbox
```

重要行为：

- 导入只复制，不移动原生书签；
- 导入不删除或修改原生书签；
- 已存在的规范化 URL 默认不可选择；
- 预览最多展示前 500 条，避免大书签库导致界面阻塞；
- 实际导入仍会再次去重；
- 每条导入记录保存原生书签 ID，仅用于追踪来源，不建立强绑定。

## 本地优先事务

云收藏写操作与同步 Outbox 使用同一个 Dexie 事务：

```text
cloudBookmarks
syncOutbox
syncVersions
```

网络不可用或用户尚未登录时，本地修改仍然保存，后续同步任务再进行推送。

## 跨设备同步

服务端使用统一 `cloud-bookmark` 实体类型。

远端变更处理：

- `upsert`：校验载荷并写入本地云收藏；
- `delete`：删除本地云收藏；
- 本地存在待推送修改时：进入同步冲突队列；
- 接受服务端版本：覆盖本地云收藏并删除冲突 Outbox；
- 保留本地版本：使用服务端最新版本号生成新 changeId 后重试。

同步不会静默采用最后写入者获胜。

## 当前限制

- 文件夹使用路径字段，尚未提供单独的文件夹重命名和层级拖拽操作；
- 尚未提供网页正文快照和 AI 自动摘要；
- 尚未提供云收藏分享；
- 尚未提供批量标签编辑；
- 尚未在真实 Supabase 项目中完成两设备集成测试。
